# T21: Camera rig (fly-to, follow, overview, auto-orbit)

## Status
Done (review approved).

## Summary
- `src/camera/cameraRig.ts`: `createCameraRig(camera, dom)` on `camera-controls` (installed with a three subset). Mouse: left rotate, right truck, wheel dolly; touch: one finger rotate, two fingers dolly+truck; `smoothTime` 0.25, `draggingSmoothTime` 0.1. `flyTo` uses `setLookAt(..., true)` with `smoothTime` 0.6 during the flight (restored at the end), focus limits `radius*1.3`..`radius*12`, distance `focusDistance(...)`, and `focusScreenOffset(layout)` applied through `camera.setViewOffset`. `flyToOverview` targets the origin at polar 60 deg with the `OVERVIEW_FIT_RADIUS` fit distance, limits 30..1600, and clears the view offset. Follow and auto-orbit (0.08 rad/s) are a rigid shift of both the current and the end state of the controls (a small `CameraControls` subclass), so a running transition continues in the body's moving frame and the user's orbit is kept. Last request wins: a newer `flyTo`/`flyToOverview` resolves the older promise at once. `setLayout` re-applies the view offset and re-frames (dolly) the focused body or the overview. `onUserInteract` listens to `controlstart`. Extra `getTarget()`.
- `src/main.ts`: rig replaces the Task 16 temporary overview camera and the Task 18 `debugCam`; the loop calls `rig.update(dt)` after `solar.update`. Selection flow (picker, labels, e2e `select`): `store.set({selected, view:'focus'})`, whoosh hook (no-op until Task 25), `rig.flyTo`. Back (`e2e overview`): `{selected:null, view:'overview'}` and `rig.flyToOverview()`. Every resize calls `rig.setLayout(layout)`.
- `src/debug/e2eApi.ts`: `debugCamTarget` removed; `E2EApi` gains `cameraTargetId()` and `projectBody(id)` (CSS px).
- Tests: `tests/unit/cameraRig.test.ts` (9), `tests/e2e/select.spec.ts` (3 x 3 projects). The `debugCamTarget` unit test in `earthRings.test.ts` was removed together with the function it tested (plan: remove `debugCam`).

## Decisions
- DECISION: flight completion = the controls' `rest` event or 2.5 s, whichever first (the plan's "about 2 s"); with `smoothTime` 0.6 a large flight would otherwise take 4-5 s to reach the 0.01 rest threshold. The remaining few units finish smoothly at the restored 0.25.
- DECISION: follow/auto-orbit shift the controls' protected current and end state together (subclass `RigControls`) instead of `setTarget`/`setPosition(false)`, which would cancel an in-flight transition, or `moveTo(true)`, which lags a fast body (Mercury about 21 units/s) by about v*smoothTime.
- DECISION: approach direction for a focus = mostly toward the sun, to the side and slightly above (the tuned T18 debugCam view), so the lit side and terminator show; for the sun itself the current viewing direction is kept.
- DECISION: focus `maxDistance` is `max(radius*12, focusDistance)` because `focusDistance` exceeds 12r on narrow portrait screens; overview `maxDistance` is `max(1600, fit distance)` likewise.
- DECISION: `flyToOverview` keeps the current azimuth (only polar and distance reset), for a shorter flight back.
- DECISION: overview clears the view offset (no panel in overview); `setLayout` also re-fits the overview distance, so rotating a phone keeps all orbits in view.
- DECISION: `rig.setLayout` is called on every resize, not only on a layout change, because the aspect (and the view-offset size) changes on any resize. `setViewOffset` resets `camera.aspect` to the canvas size, which matches the window here.
- DECISION: `CameraRig.getTarget()` added (beyond the planned interface) so `cameraTargetId()` reports what the rig is really on (matched by focus object), not what main last asked for.
- DECISION: the e2e `select`/`overview` run the same flow as the UI and resolve when the flight ends.
- DECISION: the real-tap e2e hovers before clicking on desktop and retries via `toPass` (30 s): under 3 parallel software-GL workers a stalled frame between pointerdown and pointerup can exceed the 350 ms tap limit. Alone it passes on the first try. On mobile/desktop the tap may land on Jupiter's label hit area (it starts 8 px above the body point), which also selects Jupiter.
- DECISION: `debugCam` and its unit test removed; screenshots of close-ups now use `__app.select(id)`.
