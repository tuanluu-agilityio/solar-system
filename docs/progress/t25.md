# T25: Audio engine (ambient, whoosh, narration, ducking)

## Status
Done (pending review).

## Summary
- `src/audio/audioEngine.ts`: constants (`AMBIENT_GAIN` 0.22, `AMBIENT_DUCKED_GAIN` 0.06, `NARRATION_GAIN` 1.0, `WHOOSH_GAIN` 0.35, `DUCK_RAMP_S` 0.6, plus `MUTE_RAMP_S` 0.2 and `NARRATION_LOAD_TIMEOUT_MS` 8000) and `createAudioEngine(ctxFactory?, audioFactory?)`. Graph `master` -> destination; `ambientBus`, `sfxBus`, `narrationBus` -> `master`. Nothing is created before `unlock()`; `unlock()` builds the graph and calls `resume()` synchronously (inside the gesture) and is idempotent. `setMuted` ramps the master gain 0/1 over 0.2 s (cancel + set current + linear ramp) and starts the ambient on the first unmute. Narration: one reused `HTMLAudioElement` -> `MediaElementAudioSourceNode` -> `narrationBus`; the ambient bus ramps to 0.06 over 0.6 s while it plays and back to 0.22 on `ended`/stop/`error`/load timeout/`play()` rejection. A new `playNarration` resolves the previous one `'stopped'`. `narrationTimeMs` is the element position, 0 when idle. `HTMLAudioElement.volume` is never touched.
- `src/audio/ambient.ts`: procedural ambient: detuned sine pair at 55 Hz and triangle pair at 82.4 Hz through a lowpass whose cutoff an 0.03 Hz LFO sweeps over 200-700 Hz; a looping 4 s pink-noise buffer (low-passed, very low level); shimmer sine pings at 2-6 kHz every 4-9 s with a 3-5 s exponential release. Pure helpers `pinkNoise`, `nextShimmer`.
- `src/audio/whoosh.ts`: 1.2 s white-noise burst through a bandpass swept 300 -> 2000 -> 400 Hz with an attack/exponential-release envelope; the noise buffer is cached per context.
- `src/main.ts`: engine created at boot with the persisted mute state (no context yet); a capturing `pointerdown` listener on `window` calls `unlock()`; the sound toggle calls `unlock()` then `setMuted()` and persists `sse.muted` (persistence already existed from T23); the Task 21 whoosh stub in `selectBody` is replaced by `audio.playWhoosh()`, and `backToOverview` also plays it.
- Tests: `tests/unit/audioEngine.test.ts` (17, hand-written fake `AudioContext`/`AudioParam`/nodes recording automation events, and a fake audio element), `tests/e2e/audio.spec.ts` (sound toggle -> `getState().muted`, `sse.muted` written, persists across reload both ways, no page errors).

## Decisions
- DECISION: `createAudioEngine` takes an optional second argument `audioFactory` (default `new Audio()`) so the narration element can be faked in unit tests; the planned first argument is unchanged.
- DECISION: `playNarration` before `unlock()` (or without Web Audio) resolves `'error'` at once and never plays the element, because without the gain graph it would play un-gained, bypassing mute. The tour (Task 26) then falls back to the manifest duration (Review Focus 4).
- DECISION: while muted, narration still plays into the muted master (so unmuting mid-stop is heard at the right point); `playWhoosh` while muted or before unlock does nothing (saves nodes).
- DECISION: the `pointerdown` unlock listener stays registered (capture phase) instead of `{ once: true }`: `unlock()` is cheap when running and this resumes a context iOS Safari suspended after an interruption (call, other app audio).
- DECISION: the whoosh also plays on `backToOverview`, because spec §3.7 says it plays when the camera flies to a body "or back to the overview"; the plan's wiring only names selection.
- DECISION: if the `AudioContext` constructor throws, the engine logs once and stays silent; every method is a safe no-op and `playNarration` resolves `'error'`.
- DECISION: the narration load timeout (8 s) is cleared on the element's `playing` event, so long clips are never cut off by it.
- DECISION: ramps use `cancelScheduledValues` + `setValueAtTime(current)` + `linearRampToValueAtTime` (not `cancelAndHoldAtTime`, which Firefox lacks), so a duck/restore or mute/unmute that interrupts another ramp starts from the current level.
