# T34: Wire orbit ribbons into the solar system

## Status
Done (pending review).

## Summary
- `BodyDef.orbitColor?: string` (`src/data/types.ts`); the palette from the plan lives in `src/data/bodies.ts` and `def(...)` attaches it to the 8 planets and Pluto only (Sun and Moon have none).
- `src/scene/solarSystem.ts`: one `OrbitLine` per body that has an `orbitColor` (the Moon keeps no line). `update(tSec)` sets each ribbon's planet angle from `orbitPivot.rotation.y` after the rigs update and smooths one shared emphasis with `stepEmphasis` (dt clamped to [0, 0.25], first call dt 0; no per-frame allocation). New `setViewport(w, h, pixelRatio)` and `setOrbitFocus(focused)` (target `ORBIT_STYLE.focusEmphasis` when focused, else 1).
- `src/main.ts`: `syncOrbitViewport()` (reused Vector2, `getDrawingBufferSize`, `getPixelRatio`) runs once after the solar system exists, in the resize handler after `postfx.setSize`, and in `onDowngrade` after `applyRendererSettings`. `setOrbitFocus(view !== 'overview')` runs initially and next to `labels.setVisible(...)`.
- `src/debug/e2eApi.ts` + `main.ts`: `orbitViewport()` reads the first orbit material uniforms (only installed under `?e2e=1`).
- Tests: `bodies.test.ts` (orbitColor), `solarSystem.test.ts` (new "orbit ribbons" suite replacing the interim test), `quality.spec.ts` (new spec after downgrade to low).

## Decisions
- DECISION: `orbitColor` is applied through a private `ORBIT_COLORS` map inside `def(...)` (conditional spread) instead of a sixth argument, so the 11 call sites stay unchanged.
- DECISION: one shared emphasis value for all ribbons (they always dim together), stepped once per `update`.
- DECISION: the first `update` after creation uses dt 0 (`solar.update(0)` runs at creation), so the clamp covers any later time jump (pause, tab switch).
- DECISION: the no-allocation unit test spies on `Vector3.prototype.clone`, `Color.prototype.clone` and `Array.from` during updates (a pragmatic proxy for "no scratch allocation").
- DECISION: e2e check boots once and downgrades twice (high to low), polling 25 s; the file already uses `test.slow()`.
