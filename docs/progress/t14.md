## Decisions

DECISION: `npm run narration` used forward-slash venv paths, which cmd.exe (npm's Windows shell) cannot run. Changed the script to `.venv\\Scripts\\python scripts\\generate-narration.py` (Windows-only, matching the Windows 11 target and the Windows venv layout). Verified with `npm run narration`.

DECISION: Edge TTS cue boundaries are not contiguous (first cue starts at 100 ms, small gaps and 1-50 ms overlaps). Fixed in the generator with `make_contiguous()` (first cue starts at 0, each cue starts where the previous ended, last ends at the segment duration), not in the client reader, so the committed manifest satisfies the contiguity contract. Existing manifest entries were normalized in place on the next run; no audio was re-synthesized.

DECISION: The first generation run stalled after 5 segments for more than 20 minutes with no output (no network timeout in the edge-tts call). Stopped it and reran with `python -u`. The run finished 27 of 28 segments; `moon.vi` failed after the script's built-in retries with "No audio was received". Rerunning the idempotent script generated `moon.vi`. No BLOCKED state, so no KNOWN_ISSUES entry was needed.

DECISION: `resolveSegment` returns an explicit object `{file, durationMs, cues, audio}` rather than spreading the manifest entry, so the manifest-only `hash` field does not leak into the client type. Fallback `file` is an empty string with `audio:false`.

DECISION: The fallback sentence split and proportional cue math mirror `fallback_cues()`/`split_sentences()` in the Python script, so subtitle-only timing matches the audio manifest's style.

DECISION: The asset test includes the contiguity check (cues start at 0, are contiguous, and end at `durationMs`), as requested by the lead, in addition to the spec's existence and duration checks.
