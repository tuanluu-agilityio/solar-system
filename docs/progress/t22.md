## Summary
- `src/scene/textureKeys.ts`: pure `textureKeysFor(id)` (earth: day, night, clouds; venus: atmosphere, surface; saturn: map and ring; sun: none), re-exported from `src/scene/textures.ts`, which also gains `loadHighTextures(id)` (one cached promise per body, so a body loads once).
- `src/scene/solarSystem.ts`: `SolarSystem.upgradeTextures(id, tex)` swaps the planet map, Earth `uDay`/`uNight`, the cloud map and the Saturn ring strip. Fallback stand-ins from a failed load are ignored. Replaced low textures are disposed only when no material in the scene still samples them.
- `src/main.ts`: after `rig.flyTo` resolves, if `tierSettings(quality).textureSet === 'high'` (not for the asteroid belt), `loadHighTextures(id)` then `upgradeTextures`; fire-and-forget, so `select` is not delayed.
- Tests: `tests/unit/hiresTextures.test.ts` (7), `tests/e2e/hires.spec.ts` (desktop requests `textures/high/jupiter.webp` once; iphone13 requests no high body maps).

## Verification

With default 3 parallel software-GL workers the suite is flaky on this machine (other pre-existing specs: select, boot webglUnsupported, and this one failed intermittently across runs, each passing alone and serially).

## Decisions
- DECISION: the e2e "no `textures/high/` requests" on mobile excludes `sky_*`: medium tier (mobile with more than 4 cores) loads `sky_4096` from the `high` set at boot, so only body maps are asserted.
- DECISION: the Moon, Venus and Saturn go through the same path; Venus swaps the first real key of `venus_atmosphere`, `venus_surface`. The sun is skipped (its own shader).
- DECISION: the desktop e2e uses a 90 s poll (150 s test timeout): under 3 parallel software-GL projects the flight alone can take more than 30 s.
- DECISION: if the high Saturn ring arrives while the low one was a plain band, it is switched to the textured ring.
