# T20: Picking (tap vs drag) and labels

## Status
Done (review approved).

## Summary
- `src/interaction/picker.ts`: `TAP_MAX_MOVE_PX = 8`, `TAP_MAX_MS = 350`, `isTap`, `createPicker`. Pointer events on the canvas; raycasts only on a single-pointer tap (a second pointer down during the gesture, a drag, a long press or `pointercancel` never selects). Optional 5th arg `onHover` (mouse only).
- `src/ui/labels.ts`: `createLabels` with HTML `button` labels projected each frame, hidden behind the camera, per-language names from the content modules, clickable. Extra optional `opts` (`onSelect`, `isMobile`) and `setHovered`.
- `src/ui/styles.css`: 12px labels with a `::before` hit area of at least 44 px.
- `src/main.ts`: wires picker and labels; a pick or label click sets `selected` and `view: 'focus'` in the store (camera fly-to comes in Task 21); labels hide in focus view.

## Verification
- RED: `tests/unit/picker.test.ts` failed (module missing). GREEN: 12 tests pass (tap/drag/long-press, drag ending over a hit, second pointer, dispose, label visibility rules, behind-camera, language, click).
- New e2e `tests/e2e/picking.spec.ts` (label click selects, labels hide in focus).
- lint, typecheck clean; `npm test` 325 passed; `npm run test:e2e -- --workers=1` 12 passed.

## Decisions
- DECISION: `createLabels` takes an optional fifth `opts` argument and exposes `setHovered`, because the plan signature has no way to deliver label clicks, the mobile rule or desktop hover.
- DECISION: desktop "hover" means the cursor over the body's pick proxy (picker `onHover`), not over the label itself.
- DECISION: until the camera rig exists, selection only updates the store (same as the e2e `select`).
- DECISION: `npm run format` reformats untouched files (pre-existing drift), so it was not committed; only task files are changed.
- DECISION: asteroid-belt has no label (labels cover `BodyId`s only).
