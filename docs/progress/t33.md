## Summary
- `src/bodies/orbitMath.ts` (no three import): `ORBIT_STYLE` (single source of truth for the ribbon look), `trailIntensity` (delta = planetAngle - vertexAngle wrapped to [0, 2π), `base + (head - base) * exp(-delta / tailRad)`, so the glow trails behind the motion), `ribbonProfile` (smoothstep core of half-width `coreWidthPx / totalWidthPx`, 0.5 at its edge, combined with a `haloShare` halo as `1 - (1 - core)(1 - halo)`; exactly 0 at |v| = 1), `stepEmphasis` (half-life exponential approach, negative dt = 0, lands exactly on the target for huge dt).
- `src/bodies/orbitLine.ts` rewritten: `createOrbitLine(radius, color): OrbitLine`. A closed strip of `2 * (segments + 1)` vertices (duplicated seam) and `6 * segments` indices with attributes `position` (centre line), `aSide` (-1/+1) and `aAngle` (0..2π). The vertex shader projects the centre point and a point 0.01 rad ahead along the analytic tangent, takes the pixel-space normal and offsets the clip position by `side * halfWidthPx * pixelRatio * 2 / viewport * w` (constant width in pixels; 2 because NDC spans 2 units). If either projected point has `w <= 0.001`, or the projected tangent is degenerate, the vertex collapses onto the centre line. The fragment shader mirrors `trailIntensity` and `ribbonProfile` with the constants injected from `ORBIT_STYLE` by a template literal, outputs `uColor * intensity * uEmphasis`, and has the `tonemapping_fragment` / `colorspace_fragment` includes. `ShaderMaterial` with additive blending, transparent, depthTest true, depthWrite false, DoubleSide; mesh named `orbit-line`, `frustumCulled = false`.
- Interim wiring (smallest change to keep the app compiling): `src/scene/solarSystem.ts` calls `createOrbitLine(rig.orbitRadius, '#ffffff').object`. Task 34 replaces this with per-planet colours, angle, viewport and focus updates.

## Decisions
- DECISION: `tests/unit/solarSystem.test.ts` "draws 256-segment orbit lines" changed intent on purpose (the plan supersedes the Task 17 `LineLoop` at opacity 0.15): it now asserts 9 `orbit-line` meshes with `ShaderMaterial` and `2 * (segments + 1)` vertices. Task 34 rewrites this test fully.
- DECISION: the uniforms default to a 1280x720 viewport at pixel ratio 1 until `setViewport` is called, and `setViewport` clamps sizes to at least 1, so the shader never divides by zero and the interim app draws sane widths.
- DECISION: `setPlanetAngle` stores the angle unwrapped (Task 34's test compares the uniform to `orbitPivot.rotation.y` directly); the shader wraps with `mod`. Float32 precision stays well under 0.02 rad for days of runtime.
- DECISION: `CORE_SHARE` and `CORE_FEATHER` (derived values) are exported from `orbitMath.ts` so the shader uses exactly the same numbers; the feather is `min(core / 2, 1 - core)`, so the profile stays 0.5 at the core edge and 0 at the ribbon edge for any `ORBIT_STYLE` tuning in Task 35.
- DECISION: the tangent look-ahead step is 0.01 rad (a constant in `orbitLine.ts`, not a style value).
- DECISION: `DoubleSide`, because the screen-space offset can flip the winding depending on the view.
