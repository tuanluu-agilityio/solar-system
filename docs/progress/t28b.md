# T28b: Overview polish (planet visibility, labels, Milky Way, mobile tour dock)

## Status
Done (pending review).

## Summary
Follow-up polish (controller-added) for the four open visual problems from the Task 28 review, which block the spec goal "đẹp, dễ thấy hết".
- (A) Planet visibility. `src/camera/framing.ts`: `overviewFrame()` fits the projected, tilted orbit disc (Pluto orbit + 10) inside `OVERVIEW_SAFE_NDC` {x 1, y 0.78} and returns a vertical NDC shift that centres the disc (the near rim projects larger); the rig applies it as an overview view offset. Desktop 1280x720 overview distance 561 instead of 740 (bounding-sphere fit). `overviewPolar()` looks down at 45 degrees on portrait (60 on landscape), which spreads the inner orbits. `overviewBoost()` is a screen-space minimum size: a body of display radius r is drawn at least `OVERVIEW_MIN_BODY_PX` (5, in `src/config/scale.ts`) x sqrt(r / r_earth) CSS px in radius, capped at `OVERVIEW_MAX_BOOST` (8); size order is kept and the factor drops to 1 as the camera closes in, so a focused body is never enlarged. `solarSystem.applyOverviewBoost(camera, viewH)` (called every frame) scales each body's tilt group, grows the pick proxy with it, keeps the Saturn ring-shadow radius in step, and hides the Moon (and moves its proxy to an unpicked layer) while a boosted Earth would cover its orbit.
- (B) Labels. `src/ui/labelLayout.ts` `placeLabels(items, discs, viewW)`: greedy, in priority order (hovered, Earth, Jupiter, Saturn, Mars, Venus, Mercury, Uranus, Neptune, Pluto, Sun, Moon), tries below / above / right / left of the projected (boosted) disc, drops a label that would overlap a placed label or cover another body, and keeps labels inside the view. `src/ui/labels.ts` measures each label once per text change and uses it every frame; no label for a hidden Moon.
- (C) Milky Way. `src/scene/sky.ts` now uses a small `ShaderMaterial`: linear texel minus a black point (the 1-2/255 WebP noise of empty space), x gain 14, soft shoulder to 0.6 (`SKY_TONE`, CPU mirror `skyTone()`), so the band reads clearly, empty space stays black and no star reaches the 0.85 bloom threshold (the Sun stays the only blooming, brightest element). The sphere is tilted 60.2 degrees about z (the real galactic plane to ecliptic angle; a tilt about x put a stretched texture pole in the overview) and turned -22 degrees about y so the band crosses the default overview on both layouts.
- (D) Mobile tour. While a tour is active on a phone: peek sheet 22 dvh, dock 24 px above it, disclaimer just above the sheet; the dock wraps the caption (0.85 rem) above one row with the icon-only unmute button (`.ctl-label` collapses below 768 px, `aria-label` keeps the name) and the tour controls. `rig.setTourMode()` (driven by `store.tour.status` in `main.ts`) uses `focusFill('mobile', true)` 0.3 and `focusScreenOffset('mobile', true)` y 0.38, so the body sits in the band between the top bar and the dock. Desktop is unchanged.
- Picking. Enlarged proxies of neighbouring inner planets can overlap on a phone, so the picker takes the front-most hit whose visible disc (`userData.shownRadius`) contains the tap, else the proxy centred closest to the ray relative to its size.
- `docs/KNOWN_ISSUES.md`: the four entries are marked resolved. `docs/screenshots/*.png` refreshed with `npm run test:visual`.

## Decisions
- DECISION: (A) combine a closer, disc-fitted overview (view offset centres the disc, sun slightly above screen centre) with a screen-space minimum body size instead of changing the display-scale formulas; the minimum scales with sqrt(radius) so the spec's "relative size order" is kept.
- DECISION: the boost scales each body's tilt group (sphere, clouds, atmosphere, rings) and is purely distance-based, so it never applies to a focused body and fades smoothly during flights.
- DECISION: the Moon is hidden in far views while Earth's and the Moon's shown radii exceed 0.8 x the Moon's orbit (it would sit inside the boosted Earth); it reappears when the camera is near Earth.
- DECISION: portrait overview polar 45 degrees (landscape stays 60): still oblique (spec 3.1), and the taller ellipse leaves room for inner planets and labels; the phone zoom is width-limited either way.
- DECISION: label priority puts the Sun and the Moon last (the Sun is unmistakable); on desktop the label set stays "small planets + hovered" per spec 3.1, only decluttered.
- DECISION: sky tone constants live in `src/scene/sky.ts` (not a quality number, the same in every tier); the high (4096) and low (2048) sky maps have the same brightness statistics, so one curve serves both.
- DECISION: the sky tilt is about z plus a -22 degree yaw, chosen from screenshots so the band crosses both default overviews.
- DECISION: mobile tour peek sheet 22 dvh shows the title, subtitle and back button; the expanded sheet is unchanged (88 dvh).
- DECISION: picking prefers the visible disc under the tap; every proxy carries `userData.shownRadius` (true radius by default, boosted radius in far views).
