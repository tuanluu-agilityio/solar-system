# T29: Performance and budget verification

## Status
Done (pending review). The budget passes. The real-GPU FPS run passes on mobile-throttled, but the desktop `high` overview is below 55 FPS (KNOWN_ISSUES entry).

## Summary
- `scripts/check-budget.mjs`: a cross-platform Node script (`npm run check:budget`, optional `--dist <dir>`). It walks `dist/` and sums:
  - the gzip size of all `*.js` (limit 800 KB);
  - the initial payload: JS + CSS + `index.html` + the texture and narration manifests (gzip), every `textures/low/*` file and every `low` manifest entry (includes `sky_2048`), as served (limit 8 MB).

  It prints a per-file table and PASS/FAIL lines, and exits 1 when over budget or when there is no build.
- `tests/unit/checkBudget.test.ts`: runs the script against fixture `dist` folders (pass; JS over budget; payload over budget; missing build).
- `playwright.perf.config.ts`: headed Chromium with `--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist`, 1 worker, its own preview server on port 4179. It has two projects: `mobile-throttled` (Pixel 7) and `desktop` (1440x900).
- `tests/perf/fps.spec.ts`: reads the renderer string (`WEBGL_debug_renderer_info`) and sets `gpu = !isSoftwareRenderer(...)`. It applies CDP CPU throttling x4 on mobile and measures the rAF average over 10 s in the overview (after a 5 s warm-up) and over 10 s on Saturn. It merges its section into `docs/perf-results.json` and soft-asserts the targets only when `gpu` is true. `PERF_QUALITY` forces a tier for diagnostics.
- `package.json`: `test:perf` now uses `-c playwright.perf.config.ts`; `check:budget` already pointed at the new script.
- ADR `docs/decisions/0005-performance-results.md` holds all the numbers.

## Decisions
- DECISION: the initial payload also counts the texture and narration manifests (both fetched at boot, about 9 KB gzip). WebP is counted as served; JS, CSS, HTML and JSON are counted gzip-compressed (level 9). Units are KiB/MiB.
- DECISION: the low texture set comes from `dist/textures/low/*` plus the manifest's `low` entries, so a renamed or moved sky is still counted. A `low` entry missing from the build fails the check.
- DECISION: `sky_4096` (loaded at boot on `medium`/`high`) is not counted, as the plan defines the budget with `sky_2048`. It adds 103 KB, which would still leave the payload far below 8 MB.
- DECISION: the perf server uses port 4179 with `--strictPort` and `reuseExistingServer: false`, so it never measures another worktree's build.
- DECISION: the desktop project uses deviceScaleFactor 1 at 1440x900. The mobile project uses the Pixel 7 descriptor (DPR 2.625, capped to 2 by `medium`).
- DECISION: the Saturn measurement waits 4 s after the camera target becomes Saturn, so the flight and the high-res texture swap are excluded.
- DECISION: the overview warm-up is 5 s (raised from 2 s after the first runs) so that shader compilation and texture upload are excluded.
- DECISION: the `[kind]` sections merge into the existing `docs/perf-results.json`, so `--project=desktop` re-runs keep the mobile numbers. Each section carries `qualityStart`/`qualityEnd`, pixel ratio, viewport, CPU throttle and a timestamp.
- DECISION: the targets use `expect.soft`, so both scenes are reported when one fails.
- DECISION: `src/quality/tiers.ts` is unchanged even though the desktop `high` overview misses 55 on a real GPU, for three reasons:
  - the plan's tuning step targets the mobile tiers, which pass;
  - the desktop experiments (bloom 0.75, 4000 asteroids) gave no gain beyond the ±8 FPS run-to-run noise on this shared machine;
  - lowering quality without a measured benefit contradicts §11.4.

  The miss is logged in KNOWN_ISSUES, with "lower the `high` bloom scale to 0.75" as the first lever after an idle re-measure.
- DECISION: the user brief said to run `test:perf` once. The plan requires re-measuring when a GPU misses its target, so 9 more short sequential runs were made (about 45 s each) for diagnosis.
- DECISION: added a "For HUMAN_REVIEW.md (Task 31)" section to `docs/BACKLOG.md` with two items: real-phone FPS, because the phone is emulated on a laptop iGPU, and an idle-laptop desktop re-measure.
